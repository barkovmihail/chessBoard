# Контракты клиента и сервера

- Опиши запрос и ответ маршрута схемами Pydantic. Укажи в OpenAPI успешный статус и ожидаемые ошибки. Примеры строй на шахматных данных, например ход в UCI `e2e4`. Для событий WebSocket отдельно опиши тип события, версию и содержимое снимка.
- Передавай стабильный код ошибки. На клиенте сопоставляй код с текстом и действием. При `illegal_move` игрок может выбрать другое поле. При `stale_version` клиент запрашивает свежую позицию. Общий клиент отвечает за транспорт, экран — за реакцию игрока.
- Проверяй участника и его сторону на сервере для каждой изменяющей команды. Открытие страницы через GET должно быть безопасно для предпросмотра ссылки. Занятие места и отправку хода выполняй явной командой.
- При повторной отправке той же команды используй исходный идентификатор. Связывай его с партией, участником и параметрами. Если ответ пришёл после перехода в другую партию, отбрось его. После переподключения восстанови состояние из подтверждённого сервером снимка.
